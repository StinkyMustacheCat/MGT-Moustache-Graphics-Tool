MGT 1.0.0 · PROMPT ESPECIALIZADO · IMÁGENES ESTÁTICAS

Genera una composición MGT v3 centrada en imágenes estáticas importadas por el usuario: encuadre, recorte, object-position, zoom, filtros, máscaras sencillas y movimiento determinista de marcos. No inventes imágenes, base64, rutas ni URLs; deja espacios de recurso para que MGT los importe en Propiedades.

ENTREGA
Devuelve un único JSON completo, válido y autocontenido, listo para «Código > Aplicar código». Sin Markdown, comentarios, comas finales, imports, URLs, dependencias ni fragmentos pendientes. Debe incluir `version:3`, `name`, `parameters`, `html`, `css`, `render` y `resources:{}`. `render` es el cuerpo síncrono que recibe `ctx`; no escribas una declaración de función ni uses async. Indica brevemente duración, proporción y los nombres de archivos que el usuario debe importar.

DECLARACIÓN DE IMÁGENES
Para cada espacio usa un parámetro como `{"id":"photo","label":"Imagen","type":"image","default":""}` y un recurso vacío `resources:{}`. En HTML conserva un nodo `<img data-mgt-image="photo" alt="">`; MGT lo enlaza, precarga y oculta cuando el valor está vacío. No reemplaces ese nodo con `innerHTML`. También puedes usar `const asset=ctx.image(ctx.params.photo)`: devuelve null o `{src,width,height,element}` ya decodificado; usa `src` en CSS y `element` en Canvas, sin modificarlo ni recrear imágenes dentro de render.

LÍMITES REALES
Admite PNG, JPEG, WebP estático y SVG estático seguro. Hasta 8 recursos, 10 MB por raster, 4096 px por lado, 16 MP por imagen, 32 MP raster en total y 25 MB de recursos. SVG: hasta 1 MB, 5000 elementos, 64 niveles, trazados de hasta 100 000 caracteres, sin scripts, style, use, foreignObject, image, animación, entidades ni recursos externos. No uses GIF, APNG, WebP animado, SVG animado o JPEG multipicture en esta variante.

CONTRATO DE CONTROLES
`parameters` tiene 0–48 elementos con ids únicos `^[a-zA-Z][a-zA-Z0-9_]{0,39}$`, labels no vacías de hasta 80 caracteres y defaults correctos. Tipos: `image`, `number` con `min < max`, `step > 0` y opcional `control:"slider"`, `color` (`#RRGGBB` o `#RRGGBBAA`), `boolean`, `select`, `text` y `font`. Cada ajuste declarado debe afectar realmente al render. `recommended` puede usar duration 0.1..3600, aspect `horizontal|vertical|square|classic` y resolution 480, 540, 720, 1080, 1440 o 2160.

TIEMPO Y LAYOUT
`ctx` ofrece root, params, width, height, frame, fps, time, duration, progress, seed, random(index), editingStop, image y las demás APIs de recursos. MGT usa 60 FPS: `time=frame/60` y `progress=frame/Math.max(1,N-1)`, con `N=Math.round(duration*60)`. Reconstruye el instante desde ctx para cualquier frame, también al retroceder. No uses estado acumulado, Math.random, Date, temporizadores, CSS animations/transitions, red ni promesas.

El movimiento debe estar en hijos de `root`, usando dimensiones de `ctx.width` y `ctx.height`; no cambies posición, tamaño, transform u overflow de root ni uses window.innerWidth/Height. Para un fondo editable declara color propio y asígnalo en cada render. Para recortar sin deformar usa un marco con overflow/clip-path y deja que la imagen use object-fit cover o contain. Si no hay imagen, oculta el grupo o muestra una indicación declarada.

ALCANCE
No añadas audio, vídeo base, SFX, subtítulos, pistas completas ni guardado de proyecto. Un Overlay es un JSON independiente y sus recursos no se comparten con otros clips. El JSON completo sin recursos sigue limitado a 8 MiB y cada cadena html/css/render a 2 000 000 caracteres.

REVISIÓN FINAL
Comprueba que todos los nodos `data-mgt-image` apuntan a un parámetro image, que no hay base64 inventado, que los defaults son válidos y que inicio, final y saltos hacia atrás producen el mismo encuadre esperado. Entrega al final esta solicitud:

SOLICITUD DEL USUARIO
[Describe archivos que importará el usuario, encuadre, orden de capas, movimiento, recorte, filtros, fondo, duración, proporción y controles deseados.]
