MGT 1.0.0 · PROMPT ESPECIALIZADO · 3D

Genera una composición declarativa MGT centrada en una escena 3D declarable: cámara, cajas, planos, texto 3D, modelos GLB y sus animaciones. No modifiques MGT, no inventes APIs, no uses Three.js desde `render` ni recursos externos.

ENTREGA Y DOCUMENTO
Devuelve un único JSON completo, válido y autocontenido, listo para «Código > Aplicar código». Sin Markdown, comentarios, comas finales, imports, URLs ni fragmentos pendientes. Usa siempre `version:4`, `scene3d:{version:1,...}`, `html`, `css` y `render` (pueden ser cadenas vacías cuando toda la escena sea 3D). `render` sigue siendo el cuerpo síncrono de una función que recibe `ctx`. No inventes base64 GLB: si el usuario no proporciona un archivo, declara `models:{}` y espacios de modelo con default `""`, e indica qué archivo debe importar en Propiedades.

CONTRATO COMÚN
`name` tiene hasta 100 caracteres. `parameters` tiene 0–48 controles con ids únicos `^[a-zA-Z][a-zA-Z0-9_]{0,39}$`, labels de hasta 80 caracteres y defaults válidos. Usa `number` con límites que cubran los campos 3D, `color` opaco `#RRGGBB` para la escena, `boolean`, `text`, `font`, `select` y `model` para GLB. `randomize:true` solo puede aparecer en number/color/boolean/select. `recommended` admite duration 0.1–3600, aspect `horizontal|vertical|square|classic` y resolution 480, 540, 720, 1080, 1440 o 2160.

SCENE3D EXACTA
`scene3d` solo contiene `version`, `camera`, `objects`, y opcionalmente `lighting` y `animation`. La cámara usa `x`, `y`, `distance`, `yaw`, `pitch`, `roll`, `fov`: rangos -5000..5000, distance 100..10000, yaw/roll -180..180, pitch -89..89 y fov 15..100. Declara entre 1 y 32 objetos con id único y tipo `box`, `plane`, `text` o `model`.

Cada objeto puede usar `position`, `rotation`, `scale`, `width`, `height`, `color` y `visible`. Las posiciones van de -5000 a 5000, rotaciones de -3600 a 3600, escalas de 0.05 a 10, tamaños de 1 a 3000 y colores son opacos. `box` añade `depth` de 1..3000. `text` añade `text`, `font` y `fontSize` de 12..400. `model` añade `resource` con el id de `models` o una referencia a un parámetro `model`; como máximo hay 2 objetos GLB.

MODELOS GLB
`models` contiene como máximo 2 recursos autocontenidos `{name,mime:"model/gltf-binary",data:base64}`; no inventes datos. El archivo es GLB estático o con animaciones válidas, sin referencias externas, Draco, Meshopt, KTX ni sparse. El motor limita cada GLB a 20 MB, 100 000 triángulos, 200 000 vértices, 8 texturas PNG/JPEG, 2048 px por lado, 8 MP, 32 clips y 60 000 claves. Si se declara un recurso real, enlázalo por id y no por ruta.

ANIMACIÓN Y LUZ
`scene3d.animation` tiene hasta 64 canales únicos `{target,property,from,to,start,duration,loop,smooth,enabled}`. target es `camera` o el id de un objeto; las propiedades admitidas son las de cámara y `position.x/y/z`, `rotation.x/y/z`, `scale.x/y/z`. `duration` va de 0.016667 a 3600 y `start` de 0 a 3600. En un modelo, `animation:{clip,speed,start,loop,enabled}` usa índices de clip desde 0, speed 0..4 y duración local calculable. `lighting` permite ambient 0..10, key 0..10, environment 0..5, color opaco y x/y/z -5000..5000. Todos los campos dinámicos deben referir a parámetros declarados del tipo y rango correcto.

TIEMPO Y CONTEXTO
MGT muestrea a 60 FPS: `N=Math.round(duration*60)`, `frame=0..N-1`, `time=frame/60` y `progress=frame/Math.max(1,N-1)`. El motor aplica la escena desde el instante actual y soporta saltos hacia atrás; no acumules transformaciones ni uses relojes, temporizadores, red, CSS animado ni `Math.random`. `ctx` ofrece root, params, width, height, frame, fps, time, duration, progress, seed, random(index), editingStop y las APIs de recursos; no accedas a APIs internas. Si añades HTML 2D, dibújalo con `root` y no reemplaces los nodos 3D montados.

PISTAS Y RECURSOS EXTERNOS
El JSON describe solo esta composición. No añadas audio, SFX, vídeo base, una transcripción ni el conjunto de pistas. Un Overlay se importa como JSON independiente. El guardado completo del proyecto con todos sus recursos queda fuera de esta cota.

VALIDACIÓN FINAL
Comprueba que cada referencia existe, que todos los campos `scene3d` son exactos, que el primer y último fotograma son deterministas y que el JSON no contiene base64 inventado. Entrega al final esta solicitud:

SOLICITUD DEL USUARIO
[Describe cámara, objetos, materiales de color opaco, modelo GLB opcional, luces, animaciones, duración, proporción y controles editables.]
