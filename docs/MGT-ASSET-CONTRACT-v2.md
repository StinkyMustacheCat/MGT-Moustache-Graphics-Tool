# MGT 1.6.4 — contrato local de assets v2

Este contrato convierte un `.mgt.json` o `.mgtproj` completo en **un medio audiovisual**. MGT interpreta sus pistas, código, recursos y motor de render; la aplicación anfitriona utiliza metadatos, controles declarados, progreso y el MOV resultante. Los endpoints v1 de [MGT-ASSET-CONTRACT.md](MGT-ASSET-CONTRACT.md) siguen vigentes. No hace falta abrir la interfaz de MGT.

## Inicio y seguridad

Distribuir el paquete `MGT-1.6.4-Engine-Windows-x64` completo. En Windows, la aplicación anfitriona inicia `runtime/node/node.exe motor/server.cjs` con el directorio de trabajo `motor`, `MGT_DATA_ROOT` apuntando a una carpeta **exclusiva** de esa aplicación y `CreateNoWindow=true`. El motor escucha solo en `127.0.0.1`; si el puerto configurado está ocupado prueba los siguientes. El archivo `MGT_DATA_ROOT/<instanceId>/running.json` contiene URL y PID; `instanceId` es SHA-256 de la ruta absoluta de `motor` en minúsculas, truncado a 16 caracteres. Confirmar que `/api/info` devuelve el mismo PID y versión antes de utilizarlo. No iniciar un proceso por clip: reutilizar uno para una tanda y cerrarlo al quedar inactivo.

Todas las llamadas `POST` llevan `Origin: <url-local>` y `X-Motion-Token: <token de GET /api/info>`. No divulgar el token ni exponer el puerto fuera de la máquina. El motor funciona offline: Node, Playwright Core, Chromium, FFmpeg y ffprobe están en el paquete. Chromium se inicia en modo headless al renderizar, no al inspeccionar. Para cerrar, `POST /api/shutdown`; cancela un trabajo activo, espera su terminación y puede devolver 409 si no concluye en el plazo. La aplicación anfitriona debe esperar ese cierre antes de terminar el proceso por fuerza.

## Ciclo del asset

1. `GET /api/asset/v2/capabilities`: consultar `engineVersion`, `assetContracts`, formatos, FPS, perfiles y salida. Elegir contrato 2 solo si aparece en `assetContracts`; si no, v1 admite únicamente `.mgt.json` sin overrides ni audio.
2. `POST /api/asset/v2/import` para inspeccionar. Para JSON, `Content-Type: application/json` y cuerpo `{ "format":"mgt.json", "document":<JSON MGT completo> }`. Para proyecto, `Content-Type: application/zip` y **bytes íntegros** del `.mgtproj` como cuerpo. Devuelve 201, `assetId` y el contrato inicial en perfil preview. El ID es temporal y no se guarda en el proyecto de la aplicación anfitriona: conservar el documento original e importarlo de nuevo en otra sesión.
3. `POST /api/asset/v2/preflight` con `{ "assetId":"...", "profile":"preview", "fps":24, "overrides":{} }`. Admite `profile` preview/final, FPS 15/24/30/60 y resolución 480/540/720/1080/1440/2160. Para JSON puede indicarse `duration` y `aspect`; un proyecto completo mantiene su duración. El perfil preview usa 480p por defecto; final usa la resolución recomendada del JSON o guardada en el proyecto. Es validación estructural y sintáctica, **no prueba de que cada fotograma vaya a renderizar bien**.
4. `POST /api/asset/v2/render` con los mismos campos. Devuelve 202, `id` de trabajo y el mismo contrato. Solo un render por proceso: otro devuelve 409. Consultar `GET /api/jobs/{id}`; muestra `status`, `completed`, `frames`, `error`, `fingerprint` y manifiesto de streams. Al quedar `done`, descargar `GET /api/jobs/{id}/download`. Si falla el render final, la aplicación anfitriona debe mostrar el fallo, nunca sustituirlo silenciosamente con preview.
5. `POST /api/jobs/{id}/cancel` cancela; `POST /api/jobs/{id}/release` libera el MOV cuando ya terminó la descarga. `POST /api/asset/v2/release` con `{ "assetId":"..." }` libera el documento y sus recursos; devuelve 409 si ese asset aún se está renderizando. Los assets y trabajos no liberados se podan después de una hora. Al cerrar el servidor se eliminan los temporales de la sesión.

## Metadatos y controles

`frames = round(duration × fps)` y `encodedDuration = frames / fps`. La aplicación anfitriona debe usar `frames` y `encodedDuration` para su línea de tiempo; el motor interno de MGT sigue a 60 FPS y evalúa el cuadro `round(n × 60 / fps)` para el cuadro de salida `n`. Un recorte o cambio de velocidad anfitrión opera sobre el medio resultante, no sobre el reloj interno de MGT.

La respuesta contiene `sourceFormat`, `sourceVersion`, `recommended`, `duration`, `aspect`, `resolution`, `width`, `height`, `fps`, `alpha`, `hasAudio`, `streams`, `parameters` agrupados, `dependencies`, `warnings` y `fingerprint`. `streams` anuncia ProRes 4444 con alfa y color Rec.709 SDR/rango TV; si el proyecto tiene audio, anuncia también AAC estéreo a 48 kHz. La aplicación anfitriona debe comprobar que su decodificación y composición conservan el alfa. Incluso si todas las pistas de audio están silenciadas, puede haber una pista AAC de silencio.

Cada parámetro expone `id`, `label`, `type`, `default`, `editable` y, cuando corresponda, `min`, `max`, `step`, `options` o `control`. En `.mgt.json`, el ID coincide con el parámetro de composición. En `.mgtproj`, los únicos controles expuestos son los **parámetros declarados de cada clip visual**, agrupados por clip; su ID es `clip/<id-del-clip>/<id-del-parámetro>`. No se exponen volumen, mute, orden de pistas ni controles de timeline del proyecto. Son editables los tipos `text`, `number`, `color`, `boolean`, `select` y `font`. Recursos `image`, `video`, `gif`, `svgAnimation` y `model` se informan pero no admiten reemplazo por override en v2.

`overrides` es un mapa de IDs a valores y se valida con las reglas del documento (tipo, rango, opciones). Se aplica solo al trabajo, sin modificar el original. La huella SHA-256 cambia con el contenido normalizado del JSON —o los bytes del proyecto ZIP—, overrides, perfil, FPS, fotogramas, aspecto, resolución, versión del contrato y versión del motor. La aplicación anfitriona puede usarla como clave de caché, no como prueba formal de determinismo del JavaScript. `dependencies` lista recursos empaquetados y fuentes declaradas mediante parámetros; las fuentes usadas únicamente en CSS no se enumeran por ahora.

## Proyectos y límites

El `.mgtproj` es ZIP de proyecto MGT v1/v2. Importar el archivo entero, no solo `project.json`: pueden existir WAV y vídeos de proyecto que no caben en un JSON. MGT verifica índice, integridad y referencias; un recurso faltante o corrupto causa error de importación. La composición de pistas visuales y audio se renderiza como **un solo medio**. La vista ligera y final tienen el mismo tiempo, FPS y semántica de fotogramas, aunque cambie la resolución. El audio se codifica con AAC; un `.mgt.json` individual no aporta audio de asset en este contrato.

Se aceptan documentos MGT JSON v1–v4 y proyectos v1–v2 con pistas visuales del modelo actual. Un proyecto más antiguo sin `overlayLanes` debe abrirse y guardarse primero en MGT 1.5.4 o posterior. No hay parámetros editables de audio ni transiciones MGT. El preflight detecta usos evidentes de reloj externo, red y aleatoriedad; no demuestra determinismo de JavaScript arbitrario. El motor no debe recibir composiciones de origen no confiable como si fueran código seguro. Los límites de tamaño, cantidad de recursos, duración y complejidad del motor existente siguen vigentes.

## Ejemplo verificable

En `examples/asset-v2/` están `composition.mgt.json`, `proyecto.mgtproj` (con audio de silencio), `solicitud-inspeccion.json` y `respuesta-preflight.json`. La respuesta de ejemplo se genera con MGT 1.6.4 para el JSON con `{ "profile":"preview", "fps":24, "overrides":{"color":"#00ff00"} }`; el servidor añade `assetId`, distinto en cada importación. `tests/asset-v2.integration.cjs` genera otro `.mgtproj` real con audio, lo importa y comprueba overrides de clip, previsualización/final, alfa, cancelación y salida MOV.
